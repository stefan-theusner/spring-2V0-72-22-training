# Technical writing style

## Scope

This rule applies to step-by-step guides, runbooks, and technical procedures.
It does not apply to chat answers, README overviews, or architecture prose.

Use Simplified Technical English. ASD-STE100 is the reference standard.
This project uses the style. It does not claim full standard compliance.

## Rules

1. Write one main idea in each sentence.
2. Keep each sentence at 20 words or less.
3. Use the active voice.
4. Use short, approved words.
5. Use one word for one meaning.
6. Define each new term at first use.
7. Put a condition before the action.
8. Start each step with a verb.
9. Put one action in each step.
10. Number the steps.
11. Use the same word for the same item in all steps.
12. Use **shall** for a requirement.
13. Use **can** for an ability.
14. Use **may** for permission.

## Terms

- **Action**: One operation that the reader does.
- **Condition**: A state that must be true before an action.
- **Requirement**: A rule that the reader must obey.
- **Step**: One numbered action in a procedure.

## Example

### Plain style

If you have changed the filter, the page will clear the old cards and then it will request new ones.

### STE style

If the filter changes, the page clears the old cards.
The page then requests new cards.

## Checklist

- [ ] Each sentence has one idea.
- [ ] Each sentence has 20 words or less.
- [ ] Each step starts with a verb.
- [ ] Each step has one action.
- [ ] Each new term is defined.
- [ ] **shall**, **can**, and **may** have the correct meaning.
